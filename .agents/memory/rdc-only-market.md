For Côte d'Ivoire Mobile Money deposits, use Wave only. After the user selects CI and continues, open the Wave payment instructions directly; collect the payer's phone on that same page, alongside the transaction reference and optional proof. Submit the deposit as pending for manual administration review. Do not claim automatic verification or credit; leave other countries' checkout flows unchanged.

**Why:** The user selected manual administration review, clarified that Wave is the only Côte d'Ivoire deposit operator, and repeatedly asked to remove intermediate pages before payment.

**How to apply:** Keep Wave merchant details configurable by admins; never invent or reuse a reference QR or payment URL. Enforce Wave-only for CI deposits and open directly when exactly one active Wave recipient is configured. If none or multiple are active, stay on the prior screen and show an error rather than selecting an account arbitrarily. Keep the payer-phone field on the payment page, validate the CI phone format, and keep deposit crediting behind the established admin approval flow.

Registration lists only active countries from the admin-managed country table. Login lists all configured countries, including inactive ones, so existing accounts can still sign in after deactivation. Country names, codes, and phone prefixes are not restricted by a fixed authentication allowlist. Reject registration server-side for inactive countries. Do not delete a country while accounts, payment records, wallets, deposit channels, or receiving numbers still reference it; deactivate it instead. Product prices and product earnings are entered directly as XOF and displayed as XOF without conversion. Team/referral summaries, member totals, and other visible amount labels throughout the site use XOF without conversion; stored numbers and transaction logic remain unchanged. On the « Moi » profile card only, the raw balance number is labeled FCFA without conversion. The deposit page lists every active country configured for manual deposits, regardless of the member's registration country or whether a receiving number is currently configured; load active receiving numbers only after the member chooses a country, and validate the selected country, number, and channel on submission. Do not hardcode country/operator lists. New crypto deposits accept only USDT BEP20, while existing deposit history and settlements remain intact. Withdrawals offer USDT BEP20 and active Mobile Money operator names configured for the user's country; do not expose deposit receiving numbers as withdrawal destinations.

**Why:** the user clarified that country activation in administration controls registration and login choices, while accounts from deactivated countries must remain able to sign in. The user also requires XOF display labels without conversion, FCFA only on the « Moi » balance, USDT BEP20 for crypto deposits/withdrawals, dynamically configured Mobile Money options, and Wave-only CI deposits. They explicitly require the deposit page to list all active manual-deposit countries, not only the member's registration country.

**How to apply:** load active countries for registration and all retained countries for login; enforce the active-country registration rule on the server. Keep names and phone prefixes database-driven; operators are admin-managed except that CI deposits must expose and accept Wave only. Keep withdrawal operator rules independent from this deposit restriction. Refuse deletion while stored records reference a country. Show visible monetary amounts with XOF using stored numeric values unchanged. Apply FCFA only to the « Moi » profile display; never change calculations, storage, provider amounts, payment methods, or network identifiers for a display-label request. For deposits, list every active manual-deposit country without filtering by member country or configured receiving-number presence; load and validate the exact active country, number, and matching channel when proceeding with Mobile Money. Mobile Money withdrawals remain limited to operators configured for the user's own country; only withdrawals via USDT BEP20 use NOWPayments, and historical records remain intact.
