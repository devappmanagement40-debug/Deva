description: Registration and login cover all phone regions; payment markets remain admin-managed CI and TG.

Registration and login offer the complete phone-country catalog with international calling prefixes; valid accounts may use any listed country code. Default new registrations and logins without a saved country to the United States (`US`, +1); retain a saved login country. This authentication catalog is independent of database country rows. Payment-market endpoints for deposits, withdrawals, and operators continue to expose only active `CI`/`TG` rows; do not widen payment availability just because authentication supports more countries. Preserve historical accounts, transactions, and country records in storage.

**Why:** The user requested all countries on registration and login and then asked for +1 to be the default. Existing payment operators and instructions remain configured for Côte d’Ivoire and Togo, and the user did not request a broader payment-market change.

**How to apply:** Use the shared phone-country catalog for registration/login options and server-side account validation. Keep the supported payment-market rule centralized for public deposit, withdrawal, and operator endpoints. Keep country-specific details such as CI Wave and Togo USSD/payment instructions configurable in their existing admin-managed records. Bootstrap and migration seeds must create only CI and TG; changing the authentication list must not delete or rewrite historical database records.

Registration and login use the full authentication phone-country catalog, independent of database country rows; do not block sign-up or sign-in by payment-market activation. Do not delete a country while accounts, payment records, wallets, deposit channels, or receiving numbers still reference it. Product prices and product earnings are entered directly as XOF and displayed as XOF without conversion. Team/referral summaries, member totals, and other visible amount labels throughout the site use XOF without conversion; stored numbers and transaction logic remain unchanged. On the « Moi » profile card only, the raw balance number is labeled FCFA without conversion. The deposit page lists every active supported country configured for manual deposits, regardless of the member's registration country or whether a receiving number is currently configured; load active receiving numbers only after the member chooses a country, and validate the selected country, number, and channel on submission. Do not hardcode operator lists. New crypto deposits accept only USDT BEP20, while existing deposit history and settlements remain intact. Withdrawals offer USDT BEP20 and active Mobile Money operator names configured for the user's country; do not expose deposit receiving numbers as withdrawal destinations.

**Why:** Country activation controls payment markets; authentication supports all phone-country regions. Account, payment, and withdrawal history must not be erased. Country-specific payment methods remain configurable.

**How to apply:** Keep market availability centralized to CI/TG and country-specific operators admin-managed. Refuse deleting a country while stored records reference it. Show visible monetary amounts with XOF using stored numeric values unchanged; apply FCFA only on the « Moi » profile balance. Keep Mobile Money withdrawals limited to operators configured for the user's country and USDT withdrawals on BEP20.
