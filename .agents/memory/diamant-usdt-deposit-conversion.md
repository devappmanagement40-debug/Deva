All countries use USDT for new account activity. The user explicitly wants Mobile Money deposit methods removed and the automatic XOF/USDT conversion rate no longer used. Keep USDT crypto deposits as the deposit method. Do not delete old Mobile Money records or historical XOF transactions; preserve them for audit. Legacy XOF account balances require an exact admin-entered USDT credit per account, with explicit confirmation before applying it. For new deposits, the USDT amount entered is the full amount credited to the member; DIAMANT absorbs processor fees. Quotes for other supported crypto assets must represent that entered USDT value. Disclose that wallet/network gas fees are separate and charged in the network's native asset. Customer and admin deposit screens must refer to the processor generically, never by name.

**Why:** the user now wants a site-wide USDT account currency and later superseded the earlier request to keep CI/Togo Mobile Money, explicitly asking to remove Mobile Money and the conversion rate. The user also confirmed that a deposit amount such as 300 USDT must credit 300 USDT, with processing fees borne by DIAMANT, and requested that deposit pages not name the processor.

**How to apply:** Disable Mobile Money deposits in both UI and server routes; accept deposits in USDT crypto only. Keep legacy Mobile Money deposit records unchanged. Add a protected admin workflow for manual legacy-balance credits; never infer an exchange rate or silently map an XOF amount to USDT. Keep processing fees off the member's payment amount; never promise that wallet network gas is included in the transfer amount. Use generic labels and errors on customer and admin deposit screens while retaining provider identifiers in backend processing.
